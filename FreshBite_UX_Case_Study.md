# FreshBite — Food Ordering App UI/UX
## UX-EC-001 | E-Commerce UI/UX | Mobile App UI/UX

### 1. Project Overview
FreshBite is a mobile-first food ordering experience designed around fast restaurant discovery, simple menu customization, transparent checkout, and reassuring real-time delivery tracking.

**Goal:** Create a complete end-to-end food ordering flow that is visually friendly, easy to scan, and reduces friction at the moments that matter most.

### 2. User Research & Personas
**Persona A — Aanya, Student (20)**
- Orders 3–4 times/week.
- Needs affordable meals and fast discovery.
- Pain points: too many choices, unclear delivery time, hidden fees.
- Goal: find a good meal and order in under five minutes.

**Persona B — Rohan, Professional (28)**
- Orders lunch/dinner during busy workdays.
- Values reliable ETAs, saved addresses and quick reorder.
- Pain points: slow checkout and uncertainty after placing an order.
- Goal: repeat trusted orders with minimum effort.

**Persona C — Meera, Family User (36)**
- Orders for multiple people.
- Needs clear customization and quantity controls.
- Pain points: confusing modifiers and cart mistakes.
- Goal: confidently review a larger order before paying.

### 3. User Journey
1. Open app → understand value proposition.
2. Browse/search → choose cuisine or restaurant.
3. Restaurant detail → scan rating, ETA and popular dishes.
4. Item detail → select size/extras/instructions.
5. Cart → adjust quantities and see total.
6. Checkout → confirm address/payment.
7. Tracking → understand current status and ETA.
8. Delivery → access order history/reorder later.

### 5. Wireframe Strategy
Low-fidelity structure prioritizes:
- Search near the top.
- Restaurant cards with rating + ETA.
- Persistent cart access.
- Clear primary CTA on each decision screen.
- Short forms at checkout.
- Status hierarchy on tracking.

### 7. Key UX Decisions
- Show ETA and rating directly on restaurant cards so users can compare without opening every result.
- Keep customization on the item screen to avoid an overloaded restaurant page.
- Show cart totals before checkout and again at payment.
- Use a four-stage order tracker with a clear current state.
- Use a strong, consistent pink CTA for the main action on each screen.
- Preserve familiar food-delivery patterns while keeping the interface lightweight.

### 8. Usability Testing Plan
**Tasks**
1. Find a pizza restaurant.
2. Add a customized item.
3. Change quantity in cart.
4. Complete checkout.
5. Find live order status.

**Success metrics**
- Task completion rate
- Time on task
- Checkout abandonment
- Mis-taps / navigation errors
- Confidence rating after ordering

**Expected improvements**
- Make delivery fees visible earlier.
- Keep customization labels explicit.
- Make the active tracking stage visually dominant.
- Keep one primary CTA per screen.
